# Передача оплаченного заказа в подарок

Статус: Foundation v1  
Дата: 2026-08-14

`gift_transfer` — отдельный bounded context передачи права получения существующего предоплаченного заказа. Платёж, покупатель и заказ не переносятся, второй заказ не создаётся. Активная передача переводит заказ из `PAID` в `GIFT_TRANSFERRED` и аннулирует код отправителя; отмена до принятия возвращает `PAID`, успешная подтверждённая выдача переводит заказ в `COMPLETED`, а истечение с возвратом — в `CANCELLED_BY_CUSTOMER`. Состав, цена и срок исходного заказа не меняются.

Состояния: `CREATED`, `INVITED`, `WAITING_FOR_REGISTRATION`, `AVAILABLE`, `ACCEPTED`, `REDEMPTION_READY`, `REDEEMED`, `EXPIRED`, `CANCELLED`, `RETURNED_TO_SENDER`.

Получатель определяется только по подтверждённому телефону. До регистрации хранится `GiftInvitation`, но `Customer` автоматически не создаётся. Получатель не может получить стоимость на баланс, изменить состав, доплатить или переподарить заказ. Передачу может отменить первоначальный покупатель только до принятия.

Получение подготавливает контракт Machine Runtime со статусом `FOUNDATION_ONLY`: `giftId`, `orderId`, `recipientCustomerId`, `machineId`, признак права, срок подарка, срок авторизации, одноразовость и результат выдачи. Статус `REDEEMED` разрешён только после результата `SUCCESS`; фиктивная production-выдача не создаётся. Истечение наследуется от заказа и приводит к идемпотентному возврату стоимости отправителю.

Полный телефон хранится только во внутренней модели сопоставления. Customer/Admin API возвращают маскированный номер, invitation token хранится как hash и не возвращается из операции создания подарка. Claim требует авторизованного клиента с тем же подтверждённым номером.

Prisma определяет durable target. Активный runtime v1 хранит передачи в памяти и имеет статус `FOUNDATION_ONLY` до подключения PostgreSQL-транзакций и блокировок.
