# API технического обслуживания, версия 1

Базовые маршруты: `/api/v1/maintenance` и `/api/v1/admin/maintenance`.

Все изменения требуют `Idempotency-Key`, доверенный идентификатор субъекта (`X-Operator-ID` или `X-Admin-Subject`) и роль (`X-Operator-Role` или `X-Admin-Role`). Заголовки среды разработки представляют контракт доверенного шлюза; в рабочей среде необходим проверенный контекст безопасности.

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/plans` | Создать версионируемый план профилактических или корректирующих работ для нескольких автоматов |
| POST | `/machines/identify` | Найти зарегистрированный автомат по QR-коду |
| POST | `/sessions` | Открыть эксклюзивный сеанс обслуживания автомата |
| PUT | `/sessions/:id/checklist/:itemId` | Записать результат пункта контрольного списка |
| POST | `/sessions/:id/photos` | Прикрепить неизменяемые метаданные фотографии |
| POST | `/sessions/:id/replacements` | Зарегистрировать замену и движение складской позиции |
| POST | `/sessions/:id/test-dispense` | Записать результат тестовой выдачи |
| POST | `/sessions/:id/submit` | Отправить подтверждения на согласование |
| POST | `/sessions/:id/approve` | Согласовать от имени администратора |
| POST | `/sessions/:id/reject` | Отклонить с указанием причины |
| GET | `/sessions`, `/sessions/:id` | Прочитать сеансы и неизменяемую историю аудита |
| GET | `/projection` | Прочитать очередь на основе событий и показатели |

Значения QR-кодов являются непрозрачными зарегистрированными идентификаторами. Клиенты не должны определять авторизацию или достоверность автомата по формату строки.
