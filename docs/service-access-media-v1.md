# Служебный вход и фотоотчёты, версия 1

Установлено 05.10.2026. Владелец подтвердил успешный запуск установщика: health=200, закрытые маршруты без входа возвращают 401.

Администратор, технический специалист и мастер используют одну Admin Console.
Вход: `/api/v1/admin/auth/login`; серверные сессии хранят только хэш токена.
Роли повторно загружаются на каждом запросе. Учётная запись `julcapp` подтверждена
в действующей базе как ACTIVE / PLATFORM_OWNER; владелец подтвердил смену пароля и сохранение данных входа.

Служебный кабинет: `/api/v1/service-workspace`. Мастер и техник получают аппараты
через действующие OrganizationMember, OrganizationRoleAssignment и
OrganizationMachineAssignment. Связь AdminUser → OrganizationMember добавляется
миграцией и должна назначаться администратором; без неё сотрудник не получает доступ.

Фотоотчёты хранятся в `/var/lib/soft-ice/media/service-reports` через
SERVICE_REPORT_UPLOAD_DIR, пользовательский контент выделен в
`/var/lib/soft-ice/media/user-content`. Существующие пользовательские файлы нельзя
перемещать без сверки PHOTO_UPLOAD_DIR и ссылок. Фотографии обслуживания выдаются
через авторизованный API, не через публичный Nginx location.

Фото до/после: JPEG, PNG, WebP до 8 МБ; sharp нормализует ориентацию, ограничивает
размер и преобразует в JPEG. Завершение требует оба этапа фото и описание работ.
Открытие, сохранение фото и завершение пишут AuditEvent в транзакции данных.
Управление очисткой и подключение пользовательских публикаций в каналы остаются
отдельными этапами; интерфейс обслуживания не публикует фотографии.

Проверено локально: backend 545 passed / 88 skipped; Admin Console build,
37 frontend tests. На сервере прошла приёмка в отдельном PostgreSQL-контейнере:
миграция текущей схемы, роли, назначения, фото до/после, завершение, отзыв доступа и аудит.
Рабочая база использована только для чтения структуры.
Интерфейс назначения доступен в #service-access. Для установки подготовлен
install-service-access.py: резервная копия базы и файлов, проверка конфликтов,
миграция, установка и перезапуск с проверкой закрытого доступа.
Рабочее развёртывание выполнено. Действующая служба — softice-display-backend-8800.service; прежняя soft-ice-platform-v036.service остановлена из-за конфликта порта. Резервная копия последней установки: /var/backups/soft-ice/service-access-20261005-081857. Проверка входа владельцем и назначения реальных сотрудников остаются следующим этапом.

## Два сотрудника и минимальная длина пароля

Подготовлены логины `tehnik` (SERVICE_SPECIALIST) и `master`
(MACHINE_RESPONSIBLE). Скрипт create-service-users.cjs создаёт их атомарно
в терминале владельца, выдаёт разные случайные пароли и пишет аудит. При совпадении
логинов операция отклоняется без изменения существующих записей. Членство
и назначения аппаратов не выдаются автоматически.

Оба сотрудника работают с назначенными аппаратами и своими фотоотчётами.
Просмотр технического состояния доступен технику и владельцу; мастер получает
403 при прямом обращении к API. Новые пароли: 9–128 символов в форме и на сервере.
Самостоятельная смена использует подтверждение через привязанный MAX/EMAIL;
без подтверждённого канала недоступна. Владелец подтвердил выполнение скрипта и сохранение данных обоих пользователей.

## Создание организаций и сотрудников

несвязанного логина владелец может создать карточку без изменения пароля.
Пароли 9–128 символов; коллизия логина не создаёт сотрудника.
