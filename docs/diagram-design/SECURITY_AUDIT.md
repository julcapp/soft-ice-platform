## Вывод
**Разрешить только изолированный пилот без запуска стороннего кода.**
Использовать проверенные стилевые/семантические рекомендации для генерации собственных статических HTML/SVG.
Не выполнять `npx skills add`, автоматическое обновление, неизвестные команды или сторонний экспортёр на рабочих машинах до отдельного расширенного аудита.

## Риски и меры
1. Сетевая приватность: шаблоны Diagram Design по PRIVACY.md по умолчанию запрашивают Google Fonts.
   В пилоте запретить CDN, @import, внешние скрипты, remote SVG/image/css, request/fetch.
2. Supply-chain: npm/cli, marketplace, Python dependencies, установки и обновления способны исполнять код.
   Версию зафиксировать; сначала code review конкретных install/doctor/export/import точек.
3. Сторонние файлы (Mermaid/Draw.io/Excalidraw/PlantUML) — недоверенный ввод. Не импортировать их автоматическими конвертерами без санитарной проверки, не исполнять HTML/JS из импорта.
4. DOM/XSS: только статические, экранированные лейблы; не вставлять личные данные продавцов и клиентов в публичную диаграмму.
5. Финансовая безопасность: графика не является источником истины для суммы и остатков; API/БД/логика остаются отдельными.
6. Окружение: в scripts/lint-render.py и verify-doctor.py есть логика внешних пакетов/подпроцессов для диагностики/рендера; в пилоте не запускались.
7. Licenses: MIT допускает адаптацию, при копировании стороннего кода/шаблонов сохранить текст лицензии; пилотные HTML/SVG написаны заново по принципам дизайна, исходники автора не скопированы.
8. Production: никакого deploy, изменения ПК Codex / глобальных скиллов или сервера.

## Критерии принятия
- 3 автономных HTML со встроенными SVG;
- никакой зависимости от сети;
- визуальные легенды, подписанные ветвления, различение аванса и выручки;
- статические проверки на внешние ресурсы и корректность SVG;
- все артефакты в отдельной ветке GitHub, не в production.
