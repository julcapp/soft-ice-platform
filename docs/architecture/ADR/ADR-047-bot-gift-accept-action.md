# ADR-047: Bot Core принимает подарок только через Gift Transfer Runtime

**Статус:** принято  
**Дата:** 2026-08-31

## Контекст

Bot Core поддерживает Telegram и MAX через общую модель действий, а bounded context `gift_transfer` уже владеет передачей права получения предоплаченного заказа. Кнопка в сообщении не может самостоятельно менять статус подарка и не должна обходить проверку получателя.

## Решение

1. Bot Core показывает раздел «Мои подарки» только после разрешения канальной идентичности в канонический `customerId`.
2. Callback принятия содержит только ограниченный внутренний `giftId` в формате `action:gift_accept:<giftId>`; телефон, invitation token, код выдачи и финансовые сведения в callback не помещаются.
3. Любое принятие выполняется только через `GiftTransferRuntime.accept(customerId, giftId)`.
4. `GiftTransferService` остаётся источником истины для проверки получателя, статуса, срока и идемпотентности.
5. Повторное принятие состояний `ACCEPTED` и `REDEMPTION_READY` возвращает текущее состояние без повторного события.
6. Просроченный `AVAILABLE` подарок не принимается и проходит существующий возврат отправителю.
7. После успеха Telegram может показать `DisabledButton`; при выключенном флаге завершённая кнопка скрывается. В MAX повторная кнопка принятия не отображается.
8. Подтверждение принятия является критичным бизнес-фактом и никогда не отправляется как ephemeral.
9. Код получения и запрос выдачи остаются в Mini App; Bot Core их не показывает.

## Границы

- Исходный платёж и финансовая принадлежность заказа не меняются.
- Bot Core не пишет в repository подарков напрямую.
- Исходящая доставка приглашения остаётся `FOUNDATION_ONLY/BLOCKED_EXTERNAL`, пока не утверждён безопасный provider-recipient binding для Telegram/MAX.
- Текущий in-memory Gift Transfer repository не объявляется production-durable.
- Продакшен, systemd, Nginx, токены и feature flags этим решением не изменяются.
