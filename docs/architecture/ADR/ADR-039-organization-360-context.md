# ADR-039 — Organization 360 как источник организационного контекста

Статус: Accepted  
Дата: 2026-08-16

## Контекст

Аппараты, обслуживание, инциденты, финансы и клиенты уже имеют собственные домены. Для управления бизнесом требуется единый ответ на вопросы о владельце, эксплуатирующей организации, точке, подразделении и ответственном сотруднике без копирования исходных фактов и без второго RBAC.

## Решение

Вводится отдельный bounded context Organization 360. Он владеет только организационной моделью и ссылочными назначениями. Существующий `Machine` остаётся идентичностью аппарата; Runtime и профильные домены остаются владельцами технического состояния. Показатели и события являются read-only композициями.

Tenant isolation выполняется на API и Runtime/repository boundary через доверенный organizational scope. `PLATFORM_OWNER` имеет глобальный доступ; организационный администратор ограничен одной организацией. Организационная роль не предоставляет техническое разрешение автоматически.

Изменения используют стандартный Platform Event envelope и общий аудит. Архивирование и отзыв назначений сохраняют историю.

## Последствия

Положительные: единый организационный контекст, отсутствие дублирования Machine и метрик, явная tenant boundary, готовность точек к карте, трассируемые назначения.

Ограничения: текущие Event Bus/Event Center и несколько соседних проекций остаются `FOUNDATION_ONLY`; production RLS и внешние HR/карта интеграции требуют отдельных решений.
