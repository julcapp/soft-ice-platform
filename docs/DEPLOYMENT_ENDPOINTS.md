# Домены и контуры интерфейсов

## Назначение доменов

| Домен | Назначение | Кодовая база и доступ |
|---|---|---|
| `utimoshi.ru` | Публичный сайт | Web frontend |
| `app.utimoshi.ru` | Mini App | Mini App frontend |
| `display.utimoshi.ru` | Терминал/монитор аппарата | Terminal frontend + отдельная аутентификация устройства |
| `admin.utimoshi.ru` | Административная панель | Admin Console + backend RBAC |
| `tehnik.utimoshi.ru` | Рабочее место технического специалиста | Admin Console + `SERVICE_SPECIALIST` |
| `master.utimoshi.ru` | Рабочее место ответственного за аппарат | Admin Console + `MACHINE_RESPONSIBLE` и machine scope |

Фактические DNS-записи, IP-адреса, Nginx-конфигурации и сертификаты проверяются
непосредственно перед развёртыванием и не считаются подтверждёнными только по этому документу.

## Архитектурное решение

`admin`, `tehnik` и `master` используют одну кодовую базу Admin Console.
Поддомен выбирает профиль входа и стартовый маршрут, но не выдаёт полномочия.
Доступные разделы, действия и данные определяются backend RBAC и организационным scope.

Отдельные копии Admin Console для ролей не создаются. Идентификаторы
`TECHNICIAN` и `MASTER` не используются как серверные роли.

`display` остаётся отдельным интерфейсом терминала и использует аутентификацию
устройства, а не административную сессию сотрудника.

## Условия публикации

- TLS и security headers проверены;
- маршрутизация не направляет домены на feature-ветки;
- backend отклоняет неподдерживаемые роли и чужой organization/machine scope;
- Mini App domain совпадает с зарегистрированным доменом провайдера;
- локальный и внешний `/health` успешны;
- подготовлен проверенный откат.

## Цели производительности Mini App

| Показатель | Цель |
|---|---:|
| Первый skeleton | ≤ 1 с |
| API TTFB p75 | ≤ 500 мс |
| Холодная загрузка MAX p75 / p95 | ≤ 3 с / ≤ 5 с |
| Тёплая загрузка p75 | ≤ 1,5 с |
| Профиль и баланс p75 | ≤ 800 мс |
| Ответ бота p75 / p95 | ≤ 1 с / ≤ 2 с |
| Начальный JavaScript | желательно ≤ 150 КБ gzip |

Telegram, MAX и обычный браузер измеряются отдельно. Цели изменяются только после
зафиксированных измерений и архитектурного решения.
