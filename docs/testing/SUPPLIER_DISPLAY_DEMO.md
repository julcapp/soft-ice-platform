# Демонстрация терминала для поставщика

Ветка: `feature/supplier-display-demo-v1`.
URL после публикации: `https://display.utimoshi.ru/api/supplier-demo/`.

## Назначение и ограничения

Это отдельная демонстрационная точка входа того же frontend-проекта. Используются общие визуальные компоненты и стили терминала. Рабочий `App` и существующий display index не переключаются на demo. Параметр `machineId` в демонстрации не используется; идентификатор всегда DEMO.

Экраны: ожидание, главная, ввод телефона, посыпка, топпинг, состав заказа, способы оплаты, приготовление, готовность, получение по коду/пример распознанного QR, проблемное состояние и недоступный аппарат. Панель «Все экраны демонстрации» позволяет открыть любой экран отдельно. Платёжный QR не создаётся; камера и физический сканер не запрашиваются. Код `000000` переводит к имитации приготовления, другой шестизначный код — к примеру ошибки.

Весь сеанс хранится только в React state и сбрасывается перезагрузкой. Телефон не проверяется, не отправляется и не сохраняется. Нет настоящих заказов, кодов получения, платежей, бонусов, сообщений сотрудникам или аппаратных команд.

Данные каталога — очищенный снимок публичного каталога TEST-MACHINE-001 от 15.10.2026: база 5 ₽, платные посыпки и топпинги по 1 ₽. Они явно помечены демонстрационными; это не обещание актуальной цены и не источник для расчётов боевых заказов. Клиентских данных, секретов и связей с действующими заказами в снимке нет.

## Серверная изоляция

`backend/src/supplier_demo/router.js` смонтирован отдельно на `/api/supplier-demo`. В нём нет зависимостей от БД, Payment Runtime, SDK или оборудования. Только GET/HEAD index и разрешённых статических assets; остальные методы и неизвестные действия возвращают 403 SUPPLIER_DEMO_READ_ONLY. Запрос не передаётся дальше в API compatibility/router.

CSP: `connect-src 'none'`, `form-action 'none'`, sandbox только с allow-scripts, без allow-same-origin. Это запрещает fetch/XHR/WebSocket, формы и доступ к хранилищам рабочей страницы. Permissions-Policy запрещает камеру, микрофон, оплату, USB/serial и геолокацию. Нет ссылок в рабочую админку; скрытый переход по номеру аппарата отключён только для preview.

Ограничения действуют в демонстрационном маршруте. Действующие API вне этого маршрута продолжают работать по своим правилам авторизации; demo не является способом выключить платформу целиком. Зная рабочую ссылку, человек может открыть её отдельно — поставщику передаётся именно demo URL.

## Сборка и публикация

- `node --test backend/tests/supplierDemoRoutes.test.js`
- `cd frontend/miniapp && node scripts/build-supplier-demo.mjs`
- `cd frontend/miniapp && npm run build`

Сборка IIFE отдельна от обычного Vite `dist`, чтобы работать внутри строгого sandbox без доступа к рабочим сессиям. `dist-supplier-demo` и runtime `backend/public/supplier-demo` исключены из git. На сервер переносится только demo-статика и новый router; в актуальный main вставляется одна строка после health route с предварительной проверкой SHA. Исходники main целиком не заменяются. Есть backup main и контрольные суммы обоих публичных index.

Опубликовано 15.10.2026, release `/home/julcapp/supplier-demo-release-20261015T074136Z`. Backend active. Публичные index display/admin остались без изменения; POST к demo payment/order/dispense маршрутам возвращает 403. Откат: убрать только строку монтирования demo из main, проверить `node --check`, перезапустить `softice-display-backend-8800.service`. Общие рабочие API, БД и файлы display не откатываются.

## Ручная проверка

В браузере пройдены выбор посыпки и топпинга, состав на 7 ₽, СБП-имитация, приготовление и готовность. Получение: 111111 показывает помощь, 000000 — приготовление. Перезагрузка возвращает экран ожидания. Проверены отсутствие ошибок приложения и предупреждающая полоса на всех экранах. Запросов в банк и оборудования нет.
