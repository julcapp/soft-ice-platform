# Единый порядок разработки

## Основной принцип

Одна задача — одна ветка — один Pull Request.

Работа с телефона и ПК ведётся в одном репозитории и объединяется только через GitHub. Чаты не являются источником исходного кода.

## Ветки

- `main` — стабильная версия.
- `integration/unified-v0.36.0` — единая проверяемая версия следующего релиза.
- `work/phone/<задача>` — работа с телефона.
- `work/pc/<задача>` — работа с ПК.
- `hotfix/<задача>` — отдельное срочное исправление.

Запрещено напрямую редактировать и отправлять изменения в `main` и `integration/*`.

## Начало работы

1. Выполнить `git fetch origin --prune`.
2. Создать новую ветку от актуальной `origin/integration/unified-v0.36.0`.
3. Убедиться, что рабочее дерево чистое.
4. Работать только в ветке конкретной задачи.

## Работа с телефона

1. Создать ветку `work/phone/<задача>`.
2. Делать небольшие логические коммиты.
3. После завершения каждого законченного блока отправлять ветку в GitHub.
4. Не продолжать ту же задачу на ПК до отправки телефонных коммитов.
5. На ПК сначала выполнить `git fetch`, затем продолжить существующую ветку либо создать новую ветку задачи.

## Работа с ПК

1. Создать ветку `work/pc/<задача>`.
2. Перед началом проверить обновления GitHub.
3. Не копировать файлы из другой ветки вручную без фиксации происхождения.
4. Отправить изменения и создать Pull Request в `integration/unified-v0.36.0`.

## Проверка Pull Request

Обязательны:

- отсутствие конфликтов;
- отсутствие секретов;
- проверка Prisma schema и миграций при их изменении;
- backend-тесты;
- тесты и сборка Admin Console;
- сборка Mini App;
- целевые тесты изменённого модуля;
- описание влияния на данные, API и интерфейсы;
- подтверждение, что продакшен не изменён.

## Развёртывание

1. Feature-ветки никогда не развёртываются в продакшен.
2. Сначала изменения входят в интеграционную ветку.
3. Затем выполняются тесты и приёмка.
4. Создаётся версия релиза.
5. Перед переключением systemd создаётся резервная копия.
6. После переключения проверяются локальный и внешний `/health`.
7. При ошибке выполняется откат на предыдущий релиз.

## Если телефон и ПК изменили один блок

Не объединять изменения автоматически. Создать интеграционную ветку, сравнить версии, разрешить конфликт осознанно, повторить тесты и только затем оформить Pull Request.
