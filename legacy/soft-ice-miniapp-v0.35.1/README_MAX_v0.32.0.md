# Soft_ICE v0.32.0 — адаптация Mini App для MAX

## Что изменено

- добавлена библиотека MAX Bridge через официальный адрес `https://st.max.ru/js/max-web-app.js`;
- приложение определяет среду запуска: MAX, Telegram или обычный браузер;
- клиент передаёт серверу название платформы и исходную строку `initData`;
- сервер проверяет подпись MAX по HMAC-SHA256 и ограничивает срок сессии одним часом;
- токен MAX читается только из переменной окружения `MAX_BOT_TOKEN`;
- MAX ID и Telegram ID хранятся с указанием платформы и не могут случайно совпасть;
- предзаказ, оплата, кабинет и получение заказа работают с обеими платформами;
- сохранена совместимость с ранее созданными Telegram-профилями и заказами;
- `/health` показывает только состояние настройки, но никогда не раскрывает токены.

## Важное состояние перед установкой

Токен MAX ещё не вводился. В архиве токена нет. Не добавляйте токен в `server.py`,
`tma.js`, HTML, команды запуска или скриншоты. Он должен находиться только в
`/etc/soft-ice-miniapp.env` с правами доступа `600`.

## Что пока не объединяется автоматически

MAX и Telegram используют одну базу клиентов, заказов и бонусов, но новый MAX ID
не следует автоматически связывать с существующим Telegram ID: обе платформы не
передают приложению подтверждённый номер телефона. Безопасное объединение двух
профилей будет отдельным этапом через подтверждение номера телефона.

## Проверки, выполненные перед упаковкой

- синтаксис Python: `python3 -m py_compile server.py`;
- синтаксис JavaScript: `node --check tma.js`;
- корректная подпись MAX принимается;
- неверная подпись и повторный параметр `hash` отклоняются;
- MAX-профиль создаётся отдельно от Telegram-профиля с тем же числовым ID;
- MAX-заказ проходит создание, тестовую оплату и появляется в кабинете;
- Telegram-профиль не получает доступ к заказу MAX-профиля.

## План безопасной установки на сервер

Рабочую папку `releases/v0.30/work_v0.30` напрямую не изменять. Новую сборку
распаковать в:

`/home/julcapp/soft-ice-platform/releases/v0.32.0/work_v0.32.0`

Перед переключением службы:

1. сохранить копию действующего файла службы;
2. скопировать текущий `crm_test_data.json` в новую папку, если файл существует;
3. один раз скрыто ввести токен MAX в `/etc/soft-ice-miniapp.env`;
4. установить для файла окружения права `600`;
5. переключить `WorkingDirectory` и `ExecStart` через отдельный override systemd;
6. выполнить `daemon-reload`, перезапуск и проверку `/health`;
7. проверить запуск сначала из MAX, затем из Telegram и браузера.

## Ожидаемый ответ после запуска

`GET https://app.utimoshi.ru/health` должен вернуть версию `0.32.0`, а поле
`max` — значение `configured`. Сам токен в ответе отсутствует.

## Быстрый откат

При ошибке остановить службу, отключить override версии `v0.32.0`, выполнить
`systemctl daemon-reload` и снова запустить службу. Исходная папка `v0.30` при
установке не меняется, поэтому возврат к ней остаётся возможным.
