# У Тимоши · Экран · Android 0.1.0

Отдельный Android WebView-клиент действующего `https://display.utimoshi.ru/` для смартфонов и планшетов. Это не приложение мастера/техника и не нативный драйвер TCN/MDB. Бизнес-логика сайта, каталог, платежи, статусы и команды остаются на сервере; Android-код не подтверждает оплату и не запускает выдачу сам.

Пакет `ru.utimoshi.display`, minSdk 24 (Android 7.0), target/compile SDK 35. Нужен работоспособный современный Android System WebView. Нет нативных ABI-библиотек: один APK для ARM/ARM64/x86. Камера необязательна; доступны устройства без камеры и ручной ввод кода.

По умолчанию открывается рабочий сайт с `machineId=TEST-MACHINE-001`. В меню ⋮ можно указать ID другого аппарата, перейти в безопасную supplier-demo, обновить страницу или открыть сайт браузером. ID аппарата не является авторизацией; приложение не содержит административных токенов или привязки служебного телефона.

## Возможности оболочки

- Один и тот же серверный сайт; отдельного каталога или локальной программы начислений нет.
- Переключение ориентации и размеров окна без пересоздания WebView; поддержка системных отступов и экранной клавиатуры.
- Кнопка «Назад» использует историю WebView; шаги React, не попадающие в историю браузера, проходятся экранными кнопками сайта. При закрытии — подтверждение.
- Ошибки соединения и HTTP показывают повторную загрузку; автоматическая повторная оплата не производится.
- Внутри WebView разрешены только HTTPS display.utimoshi.ru и платёжные домены yookassa.ru/yoomoney.ru. Другие HTTPS-ссылки открывает системный браузер; `intent:` используется только с безопасным HTTPS fallback. Часть банковских подтверждений может пройти вне приложения. Возврат к приложению — через Android; подтверждение факта оплаты по-прежнему обязан получить сервер. Автоматические App Links не регистрировались.
- Камера предоставляется только странице display.utimoshi.ru, вне supplier-demo, для VIDEO_CAPTURE после Android-разрешения. Микрофон не запрашивается. Отмена и отказ не блокируют ручной ввод кода.
- File/content URLs, небезопасный HTTP, смешанный контент и обход SSL отключены. Native JS bridge отсутствует. WebView debugging отключён, backup запрещён.
- Разрешения: INTERNET, ACCESS_NETWORK_STATE, CAMERA. Клиентские номера, пароли и платёжные данные оболочка не журналирует.

## Сборка

Требуются JDK 17, SDK platform 35 и build-tools 34.0.0. Gradle-описание входит в исходники, но фактический APK собран воспроизводимым SDK-скриптом без Gradle-плагина:

```
ANDROID_HOME=/path/sdk JAVA_HOME=/path/jdk17 \
UTIMOSHI_DISPLAY_KEYSTORE=/private/display-test.keystore \
python3 scripts/build-sdk.py
```

Результат: `app/build/sdk/utimoshi-display-0.1.0-test.apk`. Тестовая подпись отдельным ключом `display-test`; стандартный тестовый пароль `android`. Private keystore хранится отдельно от исходников на сборочном сервере, в каталоге 0700, файл 0600. В git/APK он не входит. Для обновления поверх установленной версии нужны тот же сертификат и повышенный versionCode. Выпуск в магазин и постоянная release-подпись — отдельный этап.

Проверка навигационной политики без Android:

```
java -m jdk.compiler/com.sun.tools.javac.Main --release 8 -d app/build/policy-test \
 app/src/main/java/ru/utimoshi/display/WebNavigationPolicy.java tests/NavigationPolicyTest.java
java -cp app/build/policy-test NavigationPolicyTest
```

## Установка и проверка на устройстве

1. Скачать APK, открыть его на Android и разрешить установку этому источнику, если Android запросит.
2. Проверить рабочий сайт, портрет/альбомную ориентацию, клавиатуру и возврат экранными кнопками.
3. Проверить камеру с разрешением и отказом, уход в фон и возврат. В supplier-demo камера должна оставаться отключённой.
4. Проверить оплату тестовым магазином до подтверждённого сервером статуса; проверить возвращение из внешнего браузера/банка.
5. Проверить временное отсутствие сети; повторная загрузка не должна создавать повторную оплату или выдачу.

На реальном смартфоне/планшете APK ещё не запускался. Компиляция и подпись не подтверждают реальную работу WebView, камеры, банковской страницы и аппаратной выдачи на конкретном устройстве. По умолчанию используется тестовый аппарат.
