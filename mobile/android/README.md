# Android · У Тимоши · Сервис 0.1.0

Тестовый нативный клиент Android 8+ (API 26), target SDK 35. Один клиент для мастера и техника; роли приходят с сервера. Первые экраны: вход, подготовка публичного ключа смартфона, выбор роли, назначенные аппараты, выход. Фотоотчёты ещё не реализованы.

Приложение создаёт ключ EC P-256 в Android Keystore. Перед первым входом администратор регистрирует публичный ключ и модель телефона через POST /api/v1/admin/service-devices/:memberId с администраторской авторизацией. Пользователь нажимает «Подготовить привязку смартфона» → «Передать данные администратору». Приватный ключ не передаётся. Приложение не регистрирует себя самостоятельно. Интерфейс регистрации в админке требует следующего этапа.

API: https://admin.utimoshi.ru; HTTP и redirects отключены, стандартная проверка TLS обязательна. Пароль и токен не сохраняются на диск. Подпись запроса привязана к точным байтам JSON, методу, пути и одноразовому challenge. Отдельные роли всегда выбираются явно. Наличие APK на другом телефоне не даёт рабочего доступа.

Обычная сборка: JDK 17, Gradle 8.9, AGP 8.7.3, Android SDK 35 и build-tools 34.0.0; `gradle assembleDebug`. Wrapper пока не создан из-за ошибки разрешения Gradle-плагина в среде сборки.

Дополнительная воспроизводимая сборка без Gradle-плагина: `ANDROID_HOME=/path/sdk SOFTICE_DEBUG_KEYSTORE=/private/path/debug.keystore python3 scripts/build-sdk.py`. Скрипт компилирует Java, D8, пакует aapt, выравнивает zipalign, подписывает apksigner. Только тестовый ключ (пароль android), не production-релиз. Существующий debug keystore надо сохранять отдельно: смена сертификата потребует переустановки и повторной привязки.

Проверено: компиляция, D8, APK подписи v2/v3, min/target SDK, доступность мобильного login через публичный HTTPS. Запуск на смартфоне, реальная регистрация устройства, успешный вход и переключение ролей ещё не проверены.
