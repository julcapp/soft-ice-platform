# TimoPOS — точки продаж, сотрудники и контроль подтверждений

**Изолированная ветка:** feature/timopos-five-points-otp-monitor-20261117.

## Выполнено в коде
- Создание стартовых пяти точек №001–005 через защищённую административную операцию (повторная последовательная инициализация не создаёт дубликаты).
- График по умолчанию: `{mode:"24_7",timeZone:"Asia/Tomsk",days:{}}`, совместим с TimoPosAccessPolicy; изменения графика по дням и часового пояса через админпанель.
- Создание/редактирование точки, регистрация продавца внутри выбранной организации и назначение на точку.
- Первый сотрудник и второй сотрудник, согласованные пользователем, должны вноситься только в реальную защищённую БД через авторизованный API. ФИО, номера телефонов, реквизиты доставки не помещаются в Git и локальные seed-файлы.
- Центр событий OTP: список отправленных запросов, каналов, статусов, времени, срока действия и безопасный отзыв; исключён вывод значения OTP, хеша и секретов. Работает по текущим моделям MAX/TimoPOS и существующим AuditEvent, без претензии на полное покрытие остальных провайдеров.

## Проверки
- 9/9 изолированных backend HTTP/политических тестов прошли на моках (пять точек, 24/7, изоляция организаций, управление журналом, отзыв кода).
- Production-сборка AdminDesktop (Vite) успешна; 39/39 тестов AdminDesktop прошли.
- Реальная PostgreSQL, действующие организации, тестовые MAX-доставки и весь поток отправки кода не проверялись.

## Блокеры перед реальными записями
- Home-Boss доступен по LAN/RDP, но Desktop Commander offline. BOSS-2 без настроенного доверенного DB runtime/подключения.
- Основной сервер 78.140.15.84 отвечает TCP на 22/80/443/5432. Доступность порта PostgreSQL требует проверки правил firewall/pg_hba; это не подтверждает возможность чтения/записи БД.
- На backend точка и продавец создаются в выбранной существующей организации, без обхода авторизации. Нужны сверка организационного идентификатора, дублей по телефонам и фактических записей.
- Нет production deployment; endpoints opt-in и не включены без runtime-зависимостей. Создание/редактирование включать после PostgreSQL интеграционных тестов и проверки миграций.
- Конкурентная инициализация пяти точек должна быть защищена уникальным DB-ограничением/блокировкой перед настоящим запуском.
