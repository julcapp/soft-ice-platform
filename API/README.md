## Правила

1. API — контракт и транспортная граница, **не** место расчёта цен, скидок, платежных решений или выдачи товара (см. `docs/api/API_OVERVIEW.md`).
2. Не путать наличие файла маршрута, его регистрацию в API и фактическое развёртывание на сервере: это три разных состояния.
3. Для каждой интеграции указывать владельца-модуль, метод/путь, авторизацию, формат, идемпотентность, тесты и статус (проект / локально / staging / production).
4. Секреты и реальные персональные данные не хранить в Git. Изменение API требует тестирования обратной совместимости.
5. Все этапы фиксировать в `stages/YYYY-MM-DD.md`, включая коммит и проверку работоспособности.
